What you get

Solutions and projectsOpens .sln, .slnx and .slnf files, with solution folders, dependencies and central package management.
Roslyn code intelligenceCompletion, navigation, find usages, inlay hints and analyser diagnostics as you type.
RefactoringsRename, extract, inline, change signature and move type to file across the solution.
NuGetSearch feeds, install, update and remove packages per project or solution, including private feeds.
Unit testsDiscover, run and debug xUnit, NUnit and MSTest tests, with results in a tree.
DebuggerBreakpoints, stepping, watches and attach to process, with netcoredbg.

Install notes

Windows

Run the installer. If SmartScreen says “Windows protected your PC”, choose More info → Run anyway (the build is not code-signed yet). The .msi suits managed installs.

macOS

Open the .dmg and drag Bayonet to Applications. The first time, right-click the app → Open (the build is not notarized yet).

Linux

Make the AppImage executable and run it, or install the package for your distribution. 
sudo apt install ./Bayonet-Linux-amd64.deb
sudo dnf install ./Bayonet-Linux-x86_64.rpm

What's new in 0.1.44

  • Update many NuGet packages at once: after Check for Updates, the NuGet window shows Update All with the number of packages that have updates. Tick the ones you want to see Update Selected instead; the box in the header ticks or clears them all.
  • Package feeds: the NuGet window's feed picker searches all enabled feeds or just one. Manage Feeds adds, edits, enables, disables and removes package sources, in your user settings or in the solution's nuget.config, the same way dotnet nuget does.
  • Open a solution or project: Open… on the welcome screen and in the File menu now accepts a .sln, .slnx or .csproj as well as a folder. A solution opens its folder with that solution chosen; a project file inside an open solution opens in the editor.

macOS builds are not notarised yet: the first time, right-click Bayonet in Applications and choose Open.
